# 个人成长系统 UI/UX 设计方案（V0.1 · 待确认）

> 本文是**方案**，不含实现。确认后再按第 9 节的节奏落地。
> 编写时间：2026-11-27。依据：当前仓库 `D:\deepseek-workspace\个人成长` 的真实代码与数据。

---

## 0 结论摘要（先看这五条）

1. **当前系统没有任何界面**：产品形态是单机 CLI + SQLite（`app/cli.py` 1300 余行），没有 HTML/CSS/JS，
   没有前端构建链，也没有页面。所以这次的活不是「美化现有页面」，而是**从零建一层本地 Web 界面**。
2. 界面必须是**只读优先**：写操作（确认/拒绝建议、改档案）继续留在 CLI，UI 先把「看得见」做好，
   避免在没有鉴权模型的情况下开放写接口。
3. **数据还不全**：`work_item` 已有约 300 条、`project` 30 条、37 篇周报月报与 2559 个片段，
   但 `capability` / `capability_evidence` / `growth_snapshot` / `growth_stage` **都是 0 条**。
   所以趋势、雷达、阶段对比这几张图**现在没有真实数据可画**，必须先设计空态，不能用假数据填充。
4. 技术路线建议：`app/web.py`（标准库 `http.server`）+ 无构建的原生 JS 静态页 + 本地内置 ECharts。
   **Python 侧仍然零第三方依赖**，前端资产是静态文件，不引入 Node 构建链。
5. 设计语言取 shadcn/ui 的**规范**（token、组件一致性）、Tremor 的**信息密度**（统计卡与趋势）、
   ReUI 的**页面组织**（侧栏 + 卡片组合）、ECharts 的**表达能力**（只在需要时用）。

## 1 现状核查

### 1.1 技术栈

| 层 | 现状 |
| --- | --- |
| 形态 | 单机 CLI，`python -m app.cli <命令>`，SQLite 单文件库 |
| 产品代码 | `app/` 12 个模块，**零第三方依赖**（`tools/check_all.py` 第 5 步强制） |
| 数据 | 44 实体 / 911 字段 / 51 枚举；`schema/schema.sql` 44 表 195 索引 |
| 数据量（2026-11-27） | 资料 37 篇、片段 2559、事项约 300、项目 30、系统 3、来源关联 100+ |
| 分析类数据 | `growth_snapshot`、`growth_stage`、`capability*`、`personal_trait`、`achievement_case` 均为 **0** |
| 前端 | **不存在**：无 `*.html`、无 `*.css`、无 `package.json`、无构建脚本 |
| 已有「可视」出口 | `overview`（文字总览）、`stats`（计数）、`trace`（追溯）——都是终端文本 |

### 1.2 因此「当前 UI/UX 的问题」是

1. **没有界面**：所有信息只能以终端表格阅读；44 个实体里真正被看见的只有 4–5 个。
2. **无法看趋势**：周报月报已经入库，但「这半年我在做什么、哪类工作在变多」只能靠翻文档。
3. **信息层级缺失**：`overview` 把数量、代表项目、近期事项、领域分布平铺成一段文字，没有主次。
4. **长文本无容器**：事项标题常是整句（如「更新预注册看板项目状态（进度70%）」），终端里挤成一行。
5. **没有边界状态设计**：CLI 出错就是一段中文报错；没有「空数据该怎么显示」「加载中」「部分失败」的规范。
6. **审核流程低效**：483 条建议只能 `ai proposals` + `ai show` + `ai confirm` 逐条敲。
7. **一致性问题不存在（因为只有一套输出）**，但一旦开始做页面，最大的风险就是「每页各写各的」——
   所以必须先立规范再动页面。

## 2 设计方向

### 2.1 产品气质

个人成长系统不是 BI 看板，也不是任务管理器。界面要传达三件事：

- **连续**：默认视角是「最近 12 周 / 最近 6 个月」，不是某一天的快照。
- **可信**：每个数字都能点回原始资料（片段 id + 原句），页面上常驻「数据来自 N 条记录」。
- **克制**：一屏最多一个主图表；没有数据就老实显示空态，不做装饰性图表。

### 2.2 参考取舍

| 参考 | 取什么 | 不取什么 |
| --- | --- | --- |
| shadcn/ui | 设计 token 与组件形态：中性灰底 + 单一主色、卡片/按钮/输入/徽章/弹窗的统一规格、`focus-visible` 环、暗色模式用同一套变量 | React/Tailwind 运行时；不引入组件库依赖 |
| Tremor | 统计卡（大数字 + 环比 + 迷你趋势）、图表标题写「结论」而不是「图表类型」、KPI 与趋势同屏 | 高饱和多色图表、堆叠式仪表盘 |
| ReUI | 左侧导航 + 顶栏 + 内容区的三栏骨架；列表页「筛选条 + 表格 + 详情抽屉」；卡片组合的留白节奏 | 重型后台模板的全部菜单层级 |
| ECharts | 折线/雷达/热力图/环图的表达力；`dataset` 驱动的配置；导出一张图的 PNG | 3D、动态特效、装饰性动画 |

## 3 设计规范（token 先行）

### 3.1 颜色

| 语义 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#FAFAFA` | `#0B0B0C` | 页面底色 |
| `--surface` | `#FFFFFF` | `#141416` | 卡片、表格 |
| `--surface-2` | `#F4F4F5` | `#1C1C1F` | 表头、悬浮态 |
| `--border` | `#E4E4E7` | `#2A2A2E` | 1px 分隔线 |
| `--text` | `#18181B` | `#F4F4F5` | 正文 |
| `--text-2` | `#71717A` | `#A1A1AA` | 次要说明 |
| `--primary` | `#4F46E5` | `#818CF8` | 主行动、选中态、主折线 |
| `--primary-weak` | `#EEF2FF` | `#1E1B4B` | 选中背景、徽章底 |
| `--success` | `#16A34A` | `#4ADE80` | 完成、增长 |
| `--warning` | `#D97706` | `#FBBF24` | 待补字段、逾期 |
| `--danger` | `#DC2626` | `#F87171` | 失败、删除 |
| `--info` | `#2563EB` | `#60A5FA` | 链接、提示 |

数据色（图表专用，按序取用）：`#4F46E5`、`#0D9488`、`#D97706`、`#DB2777`、`#7C3AED`、`#64748B`。
同一含义全站同色：**事项=主色、项目=teal、能力=紫、风险=红**。

### 3.2 字体与排版

- 字族：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；数字 `tabular-nums`。
- 字号/行高：11/16（辅助）、13/20（表格、说明）、14/22（正文）、16/24（卡片标题）、20/28（页面副标题）、28/36（页面标题）、32/40（首页大数字）。
- 字重：400 正文、500 强调与表头、600 标题与数字。
- 中文段落最大行宽 `68ch`；数字与单位之间不断行。

### 3.3 间距、圆角、阴影

- 间距基数 4：`4 / 8 / 12 / 16 / 24 / 32 / 48`；卡片内边距 20，卡片间距 16，区块间距 32。
- 布局：侧栏 232px（可折叠到 64），顶栏 56，内容最大宽 1200，页面左右留白 32（窄屏 16）。
- 圆角：输入/按钮 8、卡片 12、弹窗 16、徽章 999。
- 阴影只给浮层：`0 1px 2px rgba(0,0,0,.04)`（卡片悬浮）、`0 16px 40px rgba(0,0,0,.12)`（弹窗/抽屉）。
- 描边优先于阴影：卡片用 `1px solid var(--border)`，不堆阴影。

### 3.4 组件规范（12 个基础件）

| 组件 | 规格要点 |
| --- | --- |
| 按钮 | 高度 36（sm 28 / lg 44）；主按钮实心主色，次按钮描边，文字按钮无底；禁用 40% 透明；loading 时保留宽度 |
| 输入/选择 | 高度 36，聚焦 `2px var(--primary)` 外环 + 边框变色；错误态红边 + 下方 12px 说明 |
| 卡片 | 标题 16/600 + 可选副标题 13 `--text-2` + 右上操作区；内容区 20 内边距 |
| 统计卡 | 标签 13、数值 32/600、环比 12（增绿减红，中性灰）、底部 40px 迷你折线 |
| 表格 | 表头 13/500 `--surface-2`，行高 44，悬浮底色，首列可固定；空态占满 240px |
| 徽章 | 999 圆角、12/500、弱底 + 同色文字；状态色映射固定（进行中=蓝、完成=绿、暂停=灰、逾期=红） |
| 标签页 | 下划线式，选中 2px 主色；数量角标用弱底 |
| 抽屉 | 右侧 480px（宽屏 560），头部标题 + 关闭，底部操作条；背景遮罩 32% |
| 弹窗 | 最大宽 560，标题 18/600，主行动在右 |
| 空态 | 32px 线性图标 + 一句「为什么空」+ 一个主行动按钮；不允许只写「暂无数据」 |
| 骨架屏 | 与真实布局同尺寸的灰块，shimmer 1.4s；只在首屏加载用，翻页用行内 spinner |
| Toast | 右下角，3 秒自动消失，失败常驻并提供「重试」 |

### 3.5 图标

线性、1.5px 描边、20px 网格（`currentColor`）。全站只用一套（内置 SVG sprite，不引外部字体）。
语义固定：项目=方块叠层、事项=勾选清单、能力=雷达、复盘=回转箭头、备份=盾牌。


## 5 页面方案

### 5.1 首页（/）

**目的**：10 秒内回答「我现在什么状态、最近有没有变化、有没有要处理的事」。

布局（自下而上三段）：

1. **状态条**：左侧「当前阶段」（`growth_stage` 为空时显示「阶段未划分」，并给入口）；右侧「数据更新于 … · 覆盖 37 篇资料」。
2. **四张统计卡**：本周事项数（环比上周）、进行中项目、连续记录周数、待处理建议。
   每张卡底部一条 12 周迷你折线或进度条；**没有数据时数字显示「—」而不是 0**。
3. **两列主区**：
   - 左 2/3：**12 周事项趋势**（柱=每周事项数，线=4 周移动平均）；标题写结论，例如「近 4 周事项量比前 4 周 +18%」。
   - 右 1/3：**待处理清单**（待审建议 N 条、缺字段 M 条、逾期承诺 K 条），每条可跳到对应页面。
4. **近期时间线**：最近 10 条事项，按周分组，左侧时间轴、右侧标题 + 项目徽章 + 「来源」链接。
5. **项目组合**：进行中项目卡片（名称、角色、进度、最近更新），最多 6 张 + 「查看全部」。

图表：仅 1 个趋势图 + 2 个迷你折线。空库时整页进入「引导态」：三步（导入资料 → 提取 → 审核）。

### 5.2 成长档案（/archive）

- 二级导航：项目 / 系统 / 模块 / 事项 / 主题 / 领域（数量角标）。
- 列表页：筛选条（时间范围、状态、领域、角色、是否例行）+ 搜索 + 排序；表格列按实体不同而不同。
- 详情：右侧抽屉，字段按「概览 / 背景与目标 / 我的贡献 / 结果与影响 / 来源证据 / 变更历史」分组；
  「来源证据」是时间线（片段原句 + 资料名 + 日期），点击可看上下文。
- 顶部「档案完整度」：按必填字段与来源覆盖率算百分比，缺项可点开清单。
- 项目详情页额外有「事项构成」：该项目下事项按类型分布的小环图。

### 5.3 数据分析（/insights）

按「有数据才出现」的原则组织，每张图下面一行小字写清数据来源与条数：

| 模块 | 数据源 | 现在能否做 | 无数据时 |
| --- | --- | --- | --- |
| 成长趋势（周/月事项量 + 移动平均） | `work_item.occurred_at` | ✅ 可做 | — |
| 工作构成（事项类型 / 领域占比） | `work_item.item_type`、`work_domain` | ✅ 可做 | 领域未标注时只显示类型 |
| 活跃热力图（周 × 星期） | `work_item.occurred_at` | ✅ 可做 | — |
| 目标进度 | `project.goal` + 状态 | ✅ 可做（粗） | 项目无目标字段时提示补充 |
| 能力雷达 | `capability_evidence` × `evaluation_dimension` | ❌ 0 条 | 「能力证据还没建立」+ 第 5 步入口 |
| 阶段对比 | `growth_stage` + `growth_snapshot` | ❌ 0 条 | 「阶段分析还没生成」+ 说明 |

交互：右上时间范围（近 12 周 / 近 6 月 / 全部），全页联动；图表可导出 PNG；点击柱子下钻到该周事项列表。

### 5.4 目标管理（/goals）

**先说清一个模型事实**：当前 44 个实体里**没有独立的「目标」实体**。可用的只有
`project.goal`（项目目标文本）、`work_item.is_follow_up_needed`（需跟进）、`work_theme`（持续主题）。

因此本期页面按「项目目标 + 本周承诺」呈现：

- 上：本周承诺清单（来自最近一篇周报的 `is_follow_up_needed` 事项），完成/未完成可勾选（P2 再做写操作）。
- 中：进行中项目的目标卡（项目名、目标一句话、进度、最近更新、逾期天数）。
- 下：逾期与停滞（超过 21 天无更新的事项/项目）。

若需要真正的目标（量化指标、关键结果、周期），建议**新增 `goal` 实体**——这会改动 44→45 实体、
911 字段与闸门，属于模型变更，需要单独确认。

### 5.5 复盘（/review）

- 左：资料列表（周报/月报），显示期间、片段数、提取状态（未提取/成功/失败）、建议数。
- 右：选中的资料详情——原始片段（可折叠）+ 本次提取出的建议分组（新项目/新事项/补来源）。
- 待审队列：一屏一条建议，键盘 `J/K` 切换、`Enter` 确认、`X` 拒绝（P2 开放写操作时）。
- 顶部「本周复盘草稿」按钮：P2 之后接第 8 步的材料生成，本期置灰并说明原因。

### 5.6 设置（/settings）

- 数据：库路径、大小、各表计数、最近备份（时间/大小/校验结果）。
- 资料与索引：代码索引生成时间、闸门最近一次 9 步结果。
- 模型：网关地址、模型名、密钥来源（**只显示来源，不显示值**）、连通性检查按钮（P2）。
- 外观：主题（亮/暗/跟随系统）、密度（舒适/紧凑）。

## 6 数据可视化清单（图表 → 含义 → 数据）

| 图 | 类型 | 回答的问题 | 数据 | 降级 |
| --- | --- | --- | --- | --- |
| 周事项趋势 | 柱 + 移动平均线 | 我的产出在变多还是变少 | `work_item` 按 ISO 周聚合 | 少于 3 周→只显示柱 |
| 工作构成 | 环图 / 横条 | 时间花在哪类工作 | `item_type`、`work_domain` | 无分类→单色横条 + 提示 |
| 活跃热力图 | 日历热力 | 哪几周断更了 | 按周×星期的记录数 | 少于 4 周→不显示 |
| 项目进度 | 进度条组 | 哪些项目在推进 | `project.status` + 事项更新时间 | 无进度字段→用最近活动 |
| 能力雷达 | 雷达 | 能力结构是否均衡 | `capability_evidence` 按维度聚合 | **0 条→空态，不画** |
| 阶段曲线 | 折线 + 阶段底色 | 成长是否有台阶 | `growth_snapshot.metrics` | **0 条→空态** |
| 阶段对比 | 分组柱 | 这一阶段比上一阶段强在哪 | `growth_stage` + 快照 | **0 条→空态** |

规则：一个页面最多 2 个「大图」；每张图必须有标题结论、单位、数据条数、更新时间；
颜色不超过 5 种；不使用双 Y 轴；不使用 3D。

## 7 边界状态

| 状态 | 规范 |
| --- | --- |
| 空库 | 整页引导态：三步上手（导入 → 提取 → 审核），按钮直接给命令 |
| 空查询 | 空态组件：「这个筛选下没有记录」+「清除筛选」 |
| 加载中 | 首屏骨架屏；局部刷新用行内 spinner；超过 800ms 显示「正在读取…」 |
| 错误 | 卡片内错误块：错误码 + 一句人话 + 「重试」+「查看日志」（指向 `data/logs/app.log`） |
| 部分失败 | 顶部黄色条：「12 条建议中 2 条缺字段」，可展开清单 |
| 无权限/无凭据 | AI 相关入口禁用并注明「未配置模型密钥」，不弹窗打断 |
| 数据过期 | 顶栏时间超过 24h 显示「数据可能不是最新」 |
| 窄屏 | ≤1024 侧栏折叠为图标；≤768 单列，表格转卡片列表 |

可访问性：正文对比度 ≥ 4.5:1；所有交互可键盘到达，`focus-visible` 2px 主色环；图表提供「查看数据表」的等价文本。

## 8 技术实现（已按 React 方案落地）

### 8.1 形态

```bash
cd web && npm install && npm run build   # 首次或前端有改动时
python -m app.web --db data/growth.db --port 8765
```

- 只监听 `127.0.0.1`，单用户本地使用，不做登录。
- API 全部是只读 GET；写操作（确认/拒绝建议）仍在 CLI，P2 再评估。
- Python 侧仍零第三方依赖：`app/web.py` 用 `ThreadingHTTPServer` + `json` 提供 API，
  并托管 `web/dist`；未命中的路径回退 `index.html`（SPA 路由）。

### 8.2 目录

```
app/web.py                  # 只读 JSON API + 静态托管（标准库）
```

### 8.3 API（只读）

| 路径 | 返回 |
| --- | --- |
| `GET /api/health` | 库路径、9 张表的记录数、生成时间 |
| `GET /api/summary` | 首页统计、12 周趋势与环比、待处理建议、最近事项、项目组合 |
| `GET /api/items?q=&type=&project_id=&from=&to=&offset=&limit=` | 事项列表（服务端筛选分页） |
| `GET /api/projects` / `GET /api/projects/{id}` | 项目列表 / 详情（含事项构成与最近事项） |
| `GET /api/documents?limit=` | 资料列表 + 每篇的提取状态计数 |
| `GET /api/proposals?status=pending` | 建议列表（复盘页待处理） |
| `GET /api/insights/trend?weeks=` | 每周事项数 + 4 周移动平均 |
| `GET /api/insights/mix` | 按类型 / 领域的构成 |
| `GET /api/insights/heatmap?weeks=` | 周 × 星期矩阵 |
| `GET /api/goals` | 由真实数据算出的成长建议（`persisted: false`） |

服务端只做查询与聚合，字段名与 `schema/model.json` 一致。

### 8.4 与现有工程约束的衔接

- `tools/check_all.py` 第 5 步扫描 `app/*.py`：`web.py` 只用标准库，天然通过。
- 第 7 步密钥扫描：`web/` 源码不含任何凭据。
- 代码索引只覆盖 Python / Markdown，`web/` 的 TS 不建索引。
- 闸门不调用 `npm`（保持零 Node 依赖）；前端改动由开发者手动 `npm run build`，README 与设置页都写明。

### 8.5 设计 token 的落点

`web/src/index.css` 定义 `:root` / `.dark` 两套 CSS 变量，`tailwind.config.js` 把它们映射成
`bg-background`、`text-muted-foreground`、`border-border`、`shadow-card` 等语义类；
页面里不写字面色值（图表配色除外，集中在各页 option 里）。

## 10 已确认的四件事（2026-11-27）

1. **技术路线**：采用 **React + Vite + shadcn/ui 风格组件**，不用无构建原生方案；
   ECharts 按需注册（line / bar / heatmap），打包后约 816KB（gzip 271KB）。
2. **范围**：P0 与 P1 一起做（首页、成长档案、数据分析、成长目标、复盘、设置）。
3. **只读**：首期所有写操作留在 CLI；服务端只有 GET，不存在越权写入口。
4. **目标**：不新增 `goal` 实体。成长目标页 = 系统按真实数据算出的「下一步该补什么」
   （缺工作领域、单条记录项目、能力词典未建），明确标注 `persisted: false`。
   若之后需要可量化、可跟踪的目标，再单独评审新增 `growth_goal` 实体。
