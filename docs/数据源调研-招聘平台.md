# 招聘平台数据源调研（成长对比用）

> 调研时间：2026-11-27。目的：判断「成长与对比」所需的岗位要求、薪酬基准、同行水平，能否从招聘平台合规获取。
> 结论先行：**没有任何一家平台向个人开放「批量职位/薪酬数据」接口**；唯一官方通道是猎聘的求职者 MCP（个人授权、低频）。批量抓取 JD/简历违反平台规则且有法律风险。可行路线是「公开报告基准 + 用户自录目标 JD + 本地比对」。

## 一、结论速览

| 想要的数据 | 能拿到吗 | 合规来源 | 粒度 | 成本 |
|---|---|---|---|---|
| 行业/地区平均工资 | ✅ 能 | 国家统计局年度发布、国家数据 | 行业/地区，年度 | 免费 |
| 岗位族薪酬分位（P25/50/75） | ⚠️ 只能拿报告口径 | 智联《企业薪酬调研报告》、BOSS 直聘研究院、猎聘大数据、脉脉高聘 | 岗位族/城市/行业，年度 | 免费 PDF，需人工摘录 |
| 具体岗位 JD 与技能要求 | ⚠️ 少量、人工 | 猎聘官方 MCP（个人 Token）；用户手动复制 | 单条职位 | 免费但低频 |
| 批量 JD 入库（几万条） | ❌ 不可 | 无官方接口；爬虫违反 robots 与 ToS | — | 商用需商务合作 |
| 求职者简历 | ❌ 绝对不可 | 《个人信息保护法》，已有 2000 万元判例 | — | — |

## 二、各平台实际情况

### BOSS 直聘
- 无公开开放平台。网页端 `robots.txt` 明确禁止 `/*?query=*`、`*?position=*`、`*?city=*`、`*?salary=*`、`/wapi/zpaso/*/sem*` 等，等于把「搜索/筛选」全部排除。
- 页面数据走内部 `wapi` 接口（`zpData.jobList`），需要登录态与 `encryptExpectId` 等参数，且有风控；社区脚本（如 browser-harness）能跑通但不稳定，属违反 ToS。
- 可用的公开产出：财报与研究院新闻稿（岗位供需、平均招聘月薪等宏观指标）。

### 猎聘
- **唯一官方开放通道**：猎聘 MCP `https://open-agent.liepin.com/mcp/user`，请求头 `x-user-token`，需登录猎聘生成授权 Key；限 60 次/分钟，Token 90 天有效；能力为职位搜索、智能推荐、岗位详情、招聘信息查询，定位是「求职者 Agent」而非数据批发。来源：[MCP World 收录页](https://www.mcpworld.com/zh/detail/54fcba2abba7e9bfb0e3d10205fc2739)。
- `robots.txt` 禁止 `/*?*`（任何带参数 URL）与 `/api/com.liepin.campus*`，网页抓取没有合规空间。

### 智联招聘
- `robots.txt` 禁止 `*/api/*`、`/*.json*`、`/*?*`、`/resume*`，搜索与详情页均不在允许范围。
- 企业侧有招聘管理 API（职位发布、简历回收），但需要企业账号与商务开通，且不含公开薪酬分析数据。
- 公开产出：《企业薪酬调研报告》每年发布（2025/2026 版），含岗位族薪酬分位、城市与行业对比，是最实用的「基准」来源之一。

### 前程无忧 51job
- `https://www.51job.com/robots.txt` 返回 404（未声明），但用户协议禁止未经许可的抓取与商用。
- 内部搜索接口 `we.51job.com/api/job/search-pc` 可返回列表与 JD，属未授权接口调用；社区有采集器实现，同样不建议用于入库。

### 拉勾
- `robots.txt` 直接返回 WAF 滑块验证页，站点默认拒绝自动化访问；第三方 Apify Actor 存在（按量付费），本质仍是绕过风控。

### 脉脉
- 无面向公众的开放 API；高聘人才智库会发布《人才迁徙报告》《春招洞察》等，含新发岗位平均月薪、人才流向，可作趋势参考（需注意报告口径）。

### 第三方采集服务（Apify 等）
- 有 Zhaopin / Lagou / 51job / 中国招聘聚合的现成 Actor，输出结构化薪资与 JD，按条计费。
- 本质仍是「代你爬」：平台 ToS 未授权、数据再分发有版权与竞争法风险。个人研究可小规模试用，**不建议写入产品正式库**。

## 三、合规边界（重要）

- `robots.txt` 是技术约定，不是法律边界；真正的约束是《反不正当竞争法》《个人信息保护法》《著作权法》与平台用户协议。
- 2023 年有数据公司因爬取招聘平台**用户简历**被判赔 2000 万元、负责人承担刑责；公开 JD 的风险低于简历，但「批量抓取 + 商业化」仍可能被认定为实质性替代。
- 个人自用、少量、不存储简历、不对外分发，风险显著低于批量入库；一旦产品化/商用，应走平台商务授权或采购合规数据。

## 四、建议方案（按风险从低到高）

### 方案 A：基准表 + 自录 JD（推荐，零合规风险）
1. 内置一份「岗位基准」：行业/城市平均工资（国家统计局）+ 岗位族薪酬区间（智联/BOSS/猎聘/脉脉年度报告），每条标注来源与年份。
2. 用户在界面里粘贴 5–10 份目标岗位 JD（从任意 App 复制），系统用现有提取链路解析成「能力要求 + 经验年限 + 技能关键词」。
3. 与本人 703 条能力证据（394 条原文 + 309 条岗位链路推断）做差距对比：覆盖/缺口/强度差。
4. 数据落点：新增 `job_benchmark` 表（role、level、city、salary_p25/p50/p75、skills、source、source_url、retrieved_at），JD 解析结果先进 `change_proposal` 再确认。

### 方案 B：猎聘官方 MCP（个人低频，可选）
- 用个人 Token 在本地做「查几条同类岗位」的辅助工具，结果只作参考、不入正式库；受 60 次/分钟与 90 天 Token 限制，不适合批量。
- 需要用户自己在猎聘生成 Key，产品不代持。

### 方案 C：第三方采集（不建议）
- 仅用于一次性市场调研；不写入 growth.db、不对外分发、不碰简历。

## 五、数据可得性小结

- 「行业/城市平均工资」：稳定可得（统计局年度）。
- 「岗位族薪酬分位」：可得但是报告口径，更新慢（年度/半年），不能精确到单个岗位。
- 「实时单个岗位 JD」：可得但只能人工或官方 MCP，量小。
- 「大规模 JD 语料 / 同行能力画像」：目前没有合规且便宜的来源，属于商业化阶段才应解决的问题。
