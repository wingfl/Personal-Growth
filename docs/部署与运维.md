# 部署与运维说明

面向「把这套系统跑在自己机器上并长期使用」的场景。系统是单机 CLI + SQLite 文件，
没有服务端、没有常驻进程、没有外部数据库。

---

## 1 运行环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows（开发与验证环境）；代码本身不依赖 Windows 专有 API，Linux/macOS 可用 |
| Python | 3.11+（使用 `datetime.fromisocalendar`、`zoneinfo` 语义、`re` 与 `sqlite3` 标准库） |
| 第三方依赖 | **无**（产品代码 `app/` 只用标准库） |
| 磁盘 | 数据库 + 附件；原文片段是纯文本，万级片段约数十 MB |
| 网络 | 仅在「调模型」和「同步飞书」时需要；其余功能完全离线 |

验证环境实际使用的解释器（示例，替换为本机 Python 路径即可）：
`%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`。

**中文输出**：脚本/命令输出含中文，在 MSYS Bash 下执行时前置 `PYTHONIOENCODING=utf-8`，
否则重定向到文件会写成 GBK。

## 2 初始化

```bash
cd 个人成长

# 建库（执行 schema/schema.sql，44 张表 + 195 个索引）
python -m app.cli --db data/growth.db init

# 导入历史资料（文件、目录或 .zip）
python -m app.cli --db data/growth.db import 资料目录/ --recursive
python -m app.cli --db data/growth.db import 飞书导出.zip
```

`--db` 是全局参数，默认 `data/growth.db`。演示/试验请用单独的库（如 `data/demo.db`），
不要拿正式库做实验。

## 3 配置与凭据

### 3.1 模型（AI 能力）

`app/llm.py` 按以下顺序解析配置，先命中者生效：

1. 显式参数（`ai extract --model ...`，或 API 调用时传参）
2. 环境变量 `GROWTH_LLM_API_KEY` / `GROWTH_LLM_BASE_URL` / `GROWTH_LLM_MODEL` / `GROWTH_LLM_PROVIDER`
3. 环境变量 `NEORIGIN_API_KEY`
4. DSH profile（`~/.dsh/profiles/<profile>/cordis.patch.yml`）里的 `apiKeyEnv` / `baseURL`
5. `~/.dsh/.credentials.yaml` 的 `refs:` 段

默认网关 `https://ai-gateway.neorigin.com.cn/v1`，默认模型 `deepseek-v4-1-flash`，
默认 `max_tokens=16384`。

> 该网关的模型是**推理型**：`max_tokens` 太小会把额度全花在 reasoning 上，`content` 返回空
> （表现为 `parse_failed`）。除非明确知道在做什么，不要调低。

自检：`python -m app.cli ai check`（打印网关、模型、掩码后的密钥来源与连通性）。

### 3.2 飞书（可选）

| 身份 | 能读什么 | 需要什么 |
| --- | --- | --- |
| 应用身份 | 被显式分享给应用的内容 | 开放平台给应用开通云文档权限点 + 发布版本 + 把应用加为知识库/文件夹协作者 |
| 用户身份（OAuth） | 授权用户能看到的全部云文档 | 同上权限点 + 重定向 URL + `feishu auth` 授权一次（令牌自动续期） |

凭据与令牌存放于 `~/.dsh/.credentials.yaml` 的 `refs:` 段（键：`FEISHU_APP_ID`、
`FEISHU_APP_SECRET`、`FEISHU_USER_ACCESS_TOKEN`、`FEISHU_USER_REFRESH_TOKEN`、
`FEISHU_USER_EXPIRES_AT`、`FEISHU_USER_SCOPE`、`FEISHU_USER_REFRESH_EXPIRES_AT`）。
每次写入前自动备份为 `.bak-YYYYmmdd-HHMMSS`。也可用工作区本地文件 `config/feishu.json`
（已加入 `.gitignore`）。

自检：`python -m app.cli feishu check`（打印身份模式、可见知识库数、云盘是否可读、以及具体缺失的权限点）。

### 3.3 密钥安全约定

- 密钥只出现在进程内存与上述凭据文件里；**不写数据库、不进版本库、不进日志**。
- 所有对外输出只用掩码（`sk-3cy…FFLb`、`cli_aa5d…1cf1`）。
- `tools/check_all.py` 会扫描仓库，防止凭据被误提交。

## 4 目录与数据文件

```
个人成长/

├─ 样例资料/        三份演示资料（示例内容，可删）
├─ 飞书导出/        从飞书导出的原始资料（不进版本库）
└─ data/           数据库、附件、演示日志（不进版本库）
```

**数据库与附件必须一起备份**：附件按 `<数据库同目录>/attachments/<内容哈希前12位>_<原文件名>` 存放，
`attachment.storage_path` 尽量记工作区相对路径，跨盘符时记绝对路径。

## 5 日常操作

```bash
# 资料
python -m app.cli --db data/growth.db import <路径> [--type weekly_report] [--handling skip|new_version|import_anyway] [--recursive]
python -m app.cli --db data/growth.db docs                 # 资料列表（类型/期间/片段数/字数）
python -m app.cli --db data/growth.db verify <文档ID>       # 逐片段校验字符区间与正文一致 + 正文哈希
python -m app.cli --db data/growth.db fragments <文档ID>    # 片段清单

# 档案（第 3 步）
python -m app.cli --db data/growth.db project add "名称" --from <片段ID> ...
python -m app.cli --db data/growth.db item add "标题" --type development --from <片段ID>
python -m app.cli --db data/growth.db overview             # 总览计数、时间范围、领域分布、待审建议数
python -m app.cli --db data/growth.db trace project <ID>   # 来源片段 + 实体关联 + 变更历史

# AI 提取与审核（第 4 步）
python -m app.cli --db data/growth.db ai seed              # 把 prompts/*.json 同步进库（改过提示词必须重跑）
python -m app.cli --db data/growth.db ai check
python -m app.cli --db data/growth.db ai extract <文档ID> [--dry-run]
python -m app.cli --db data/growth.db ai proposals [--status pending]
python -m app.cli --db data/growth.db ai show <建议ID>
python -m app.cli --db data/growth.db ai confirm <建议ID> [--set 字段=值 ...] [--note "..."]
python -m app.cli --db data/growth.db ai reject <建议ID> [--note "..."]
python -m app.cli --db data/growth.db ai jobs              # 作业清单（模型、用时、token、产出条数）

# 飞书
python -m app.cli --db data/growth.db feishu check
python -m app.cli --db data/growth.db feishu auth          # 用户身份授权（浏览器打开链接）
python -m app.cli --db data/growth.db feishu scan --source wiki --match 周报,月报
python -m app.cli --db data/growth.db feishu pull --source wiki --match 周报,月报
```

## 6 备份与恢复

当前**没有** `backup` 子命令（`backup_record` 表已建好，写入方属于第 10 步），所以备份走文件系统：

```bash
# 备份（数据库 + 附件一起，务必成对）
python - <<'PY'
import sqlite3, pathlib, datetime
src = pathlib.Path("data/growth.db")
dst_dir = pathlib.Path("backup"); dst_dir.mkdir(exist_ok=True)
stamp = datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
dst = dst_dir / f"growth-{stamp}.db"
con = sqlite3.connect(src); con.execute("VACUUM INTO ?", (str(dst),)); con.close()
print("已备份:", dst)
PY
cp -r data/attachments backup/attachments-<stamp>/
```

`VACUUM INTO` 是 SQLite 官方推荐的热备方式（自动处理 WAL），比直接复制 `.db` 文件安全。

**恢复**：停掉正在运行的命令 → 用备份的 `.db` 覆盖 `data/growth.db` → 把对应批次的
`attachments/` 放回数据库同目录 → 跑 `python -m app.cli --db data/growth.db stats` 与
`verify` 抽查，确认记录数与片段偏移正常。

**导出（跨工具迁移）**：`schema/schema.sql` 是标准 SQLite DDL；
`docs/个人成长档案系统-数据模型字段清单 V1.0.xlsx` 可供人阅读；
机器可读的全量导出属于第 10 步（需求 1.4⑧「正式数据支持导出和迁移」）。

## 7 升级与迁移

模型变更（新增字段/枚举/索引）的标准流程：

```bash
# 1) 改 schema/model.core.json 或 schema/parts/*.entities.json
# 2) 重新生成 model.json / schema.sql / 字段文档 / xlsx（自带一致性校验，失败即非零退出）
PYTHONIOENCODING=utf-8 python tools/build_model.py
# 3) 给已有数据库补列补索引（先 dry-run 看要改什么）
PYTHONIOENCODING=utf-8 python tools/migrate_db.py --all --dry-run
PYTHONIOENCODING=utf-8 python tools/migrate_db.py --all
# 4) 全量质量闸门（含 102 条单元测试）
PYTHONIOENCODING=utf-8 python tools/check_all.py
```

代码升级同理：改 `app/` 后跑第 4 步，确认既有功能未被破坏。

> `tools/oneoff/` 下是一次性补丁脚本，**不可重跑**（它们是断言式的，改完即失效）。真正可重复
> 执行的迁移工具只有 `tools/migrate_db.py`。

## 8 巡检与健康检查

| 命令 | 检查什么 |
| --- | --- |
| `python tools/check_all.py` | 模型构建、生成物一致性、DDL 实跑、编译、密钥扫描、全量测试 |
| `python -m app.cli --db <库> stats` | 各实体记录数、审计条数 |
| `python -m app.cli --db <库> verify <文档ID>` | 片段字符偏移是否仍能精确切回正文（解析一致性） |
| `python -m app.cli --db <库> audit --entity work_item --id <ID>` | 单条记录的完整变更历史 |
| `python -m app.cli ai check` / `feishu check` | 外部依赖连通性与权限 |
| `python -m app.cli --db <库> overview` | 业务视角总览（含待审建议数，正常应为 0 或少量） |

建议：每次批量导入后跑一次 `verify`；每次模型变更后跑 `check_all.py`；定期备份。

## 9 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `sqlite3.OperationalError: no such column: xxx` | 数据库比模型旧 | `python tools/migrate_db.py --all` |
| `错误：未知字段 xxx` | 字段名拼错，或模型未重新生成 | 改 core/parts 后跑 `build_model.py` |
| `错误：找不到提示词模板…请先运行 ai seed` | 新库里没有 prompt_template | `ai seed` |
| `parse_failed` + `模型没有返回内容（finish_reason=length）` | `max_tokens` 不够（推理型模型） | 用默认 16384，或 `--max-tokens` 调大 |
| `invalid_input` / HTTP 401、403 | 模型密钥无效或未授权 | 检查 `ai check` 输出的密钥来源，更新凭据 |
| `rate_limited` / HTTP 429 | 触发网关限流 | 稍后重试；`ai_job` 已记录失败原因 |
| 飞书 `code=99991672` | 应用缺少云文档权限点 | 开放平台开通（应用身份/用户身份两栏都要看）并**发布版本**；或改用用户身份 OAuth |
| 飞书读不到「我的空间」 | 应用身份看不到用户私有文档 | `feishu auth` 走用户身份；或让用户导出到 `飞书导出/` 由 `import` 入库 |
| 附件丢失/路径失效 | 只备份了 `.db`，没备份 `attachments/` | 从备份恢复附件目录；`storage_path` 跨盘符时可能是绝对路径 |
| `Conflict`（乐观锁） | 同一记录被并发修改 | 重新读取后重试（CLI 场景基本不会遇到） |
| `imm` 字段拒绝修改 | 试图改原始正文/引用原文 | 这是设计约束（需求 1.4①）；需要修正请新增记录并保留旧记录 |

## 10 安全与隐私

- **数据不出本机**，除了两处明确的对外调用：
  1. **调模型时**：会把「本次资料的原文片段 + 档案中已有记录的名称 + 字段取值口径」发送到你配置的
     模型网关（默认 `ai-gateway.neorigin.com.cn`）。也就是说被提取的那份资料内容会离开本机。
     处理涉密资料时请用 `--dry-run` 先看会发出去什么（`ai extract --dry-run` 打印完整请求内容）。
  2. **飞书同步**：只读取，不写入飞书。
- 数据库是**明文** SQLite 文件，依赖操作系统文件权限保护；`data/` 与 `飞书导出/` 已加入 `.gitignore`。
- 凭据集中在一处（`~/.dsh/.credentials.yaml`），写入前自动备份；对外输出一律掩码。
- 审计留痕：所有档案写入（含 AI 建议确认）都记 `audit_log`，含前后 payload、操作者类型、
  关联的 `proposal_id`/`job_id`，可按记录查询（`audit`、`trace`）。
- 原始内容不可修改：`raw_text`、片段 `text`、`quote_text` 写入后拒绝更新，保证「证据」的完整性。
